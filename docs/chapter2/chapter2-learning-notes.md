# 第二章学习笔记：智能体的发展历史

> 对应阅读：`Chapter2-History-of-Agents.md`。核心问题：**现代 Agent 的模型、规划、记忆、工具和反馈机制从何而来？**

## 一、先抓住发展主线

| 思路 | 能力从哪里来 | 主要贡献 | 主要局限 |
|---|---|---|---|
| 符号主义 | 人编写的知识与逻辑规则 | 在明确、封闭的领域里推理和规划 | 知识难穷举，遇到例外容易失效 |
| 心智社会 | 专门模块之间的分工与协作 | 解释复杂行为如何由简单能力组合而成 | 需要解决协调与故障处理 |
| 连接主义 | 数据训练出的神经网络参数 | 从图像、声音、文本中学习表示与模式 | 学会识别模式，不等于学会长期决策 |
| 强化学习 | 与环境交互得到的奖励反馈 | 学习一连串动作的策略 | 交互成本高，奖励设计困难，常缺少先验知识 |
| 预训练与 LLM Agent | 预训练模型，结合记忆、规划和工具 | 处理开放指令，并根据结果调整行动 | 模型输出和工具执行仍需核验与约束 |

这些是理解 Agent 的几条技术与思想线索，并非严格的先后阶段。现代 Agent 仍用明确规则约束工具，用模块分工完成任务，并借助模型处理难以手工枚举的语言和知识。

## 二、符号主义：把知识写出来，再按规则推理

### 物理符号系统假说（PSSH）

艾伦·纽厄尔（Allen Newell）和 赫伯特·西蒙（Herbert A. Simon）提出：符号及其操作过程与一般智能有根本关系。它包含两个不同的主张：

- **充分性**：任何一个物理符号系统，都具备产生通用智能行为的充分手段。
- **必要性**：任何一个能够展现通用智能行为的系统，其本质必然是一个物理符号系统。

**PSSH 宣称智能的本质，就是符号的计算与处理。但这是理论假说，不能把早期系统的成功当作对它的完整证明。**

### 专家系统：知识库 + 推理机

```text
领域知识 → 知识库（IF 条件 THEN 结论）
用户事实 → 推理机匹配规则 → 新结论／继续询问 → 建议
```

- **知识库**存放某个领域的知识和经验，常用 `IF-THEN` 产生式规则。
- **推理机**负责根据事实，选择相应规则，从而推导出新的结论，工作方式有两种：
  - **前向推理**从已知事实出发，不断推出新事实；适合问“这些事实会导致什么？”
  - **后向推理**从待验证的目标倒推所需条件；适合问“要证明这个结论，还缺什么证据？”

书中的 **MYCIN** 根据症状、病史等信息辅助诊断，并用确定性因子（CF）表示证据对结论的支持程度。它说明规则系统在**边界清楚的专业任务**中可以有效，但知识采集和维护高度依赖专家。

### SHRDLU：封闭世界中的“感知—思考—行动”

SHRDLU 在“积木世界”中把自然语言解析、环境状态、规划、动作和记忆连在一起。例如要把蓝色积木放到红色积木上，如果红色积木被挡住，就得先移开障碍，再执行放置。这已经很像第 1 章的 Agent Loop。

它的成功依赖于**世界小、规则完整、对象与动作有限**。把同一套方法搬到开放现实环境时，系统很难预先知道所有情况。

### 为什么规则越写越难用？

1. **知识获取与常识问题**：大量常识和专家经验难以明确表达，逐条整理、编码的成本很高。
2. **框架问题**：执行一个动作后，哪些状态发生变化、哪些保持不变？若都要求显式写规则，复杂度会迅速增加。
3. **脆弱性**：输入稍超出预设情形，系统可能找不到合适规则，或套用错误规则。

**要点：** 规则很适合表达明确约束；它难以单独承担开放环境中的全部理解和决策。

## 三、ELIZA：看似会聊天，实际在匹配模板

ELIZA 的经典 `DOCTOR` 脚本通过提问维持对话。它的基本流水线是：

```text
用户输入 → 找关键词／匹配模式 → 截取句子片段
         → 人称转换（my → your）→ 套入回复模板 → 输出
```

例如输入 `I need some help`，程序匹配 `I need (.*)`，截取 `some help`，再套用模板生成 `Why do you need some help?`。用户可能把这种连贯的追问理解为“机器懂我”，这正是 **ELIZA 效应**所揭示的现象。

**原理与示例有区别：** 原理介绍包含关键词优先级、分解与重组；本章的简化 Python 示例按规则顺序进行正则匹配，再随机选一个回复模板，没有完整实现关键词优先级。

| 现象 | 原因 |
|---|---|
| 对陌生话题只会泛泛追问 | 没有相应规则，只能落到兜底模板 |
| 多轮对话前后不连贯 | 示例每次只处理当前输入，没有对话状态 |
| 否定、歧义和上下文容易处理错 | 字符串匹配不等于语义理解 |
| 规则越多越难维护 | 模式可能重叠、冲突，优先级变复杂 |

**与第 1 章 ReAct 对照：** ELIZA 的回复由预设匹配和模板直接决定；ReAct 让模型根据当前目标和历史观察选择下一步行动，并把工具结果送回下一轮。两者都可循环交互，但决策来源和可处理的问题范围不同。

## 四、心智社会：复杂能力来自分工协作

Minsky 的“心智社会”提出：一个复杂任务可以由许多功能简单的“小 agent”协同完成。这里的 **agent 是专门的心智过程**，不是今天通常说的完整 LLM Agent，不能直接画等号。

以“搭积木塔”为例：`BUILD-TOWER` 激活搭建流程，流程调用 `FIND-BLOCK`、`GET-BLOCK`、`PUT-ON-TOP` 等子过程；底层的 `GRASP` 只负责抓取，不需要理解“塔”的完整目标。整体行为来自各部分的连接、激活和协调。

这为多智能体系统提供了一个思路：**把任务拆成职责清晰的单元，再设计它们如何通信和配合**。但拆分本身不保证效果；如果 `GRASP` 失败，上层流程需要获知失败并重试或重新规划。

## 五、从“人工写知识”走向“从经验中学习”

### 连接主义：知识分布在参数中

神经网络通过训练调整参数，不要求开发者把每条知识都写成 `IF-THEN`。系统由此能从文本、图像等数据中学习表示和模式。**显式规则**容易逐条检查、修改；**参数中的知识**较难定位和解释。

### 强化学习：在交互中学习策略

```text
观察状态 Sₜ → 按策略 π 选择动作 Aₜ
             → 环境转到 Sₜ₊₁，返回奖励 Rₜ₊₁
             → 用反馈改进策略
```

强化学习的目标是提高**长期累计奖励**，不是每一步都只拿眼前最高分。围棋就是典型的序列决策：某一步可能暂时吃亏，却提高最终获胜机会。

它与监督学习的区别在于：监督学习通常从带“正确答案”的样本学习；强化学习通过行动、环境反馈及奖励学习“在什么状态下做什么”。

### 大规模预训练：给 Agent 一套通用起点

预训练让模型从大量数据中学习语言模式和一定的背景知识，再通过微调或上下文示例适配任务。这样，每个新任务不必完全从零开始。

- **上下文学习**：在提示中给少量示例即可改变当前任务的表现，通常不改模型参数。
- **微调**：继续训练模型以适配任务，会改变模型参数。
- **分步推理提示**：引导模型分解复杂问题；写出步骤不代表每一步都正确，仍需核验。

预训练缓解了手工录入知识的瓶颈，但模型可能生成错误或过时内容。Agent 仍需用工具获取信息、核验结果，并约束可执行的动作。

## 六、回到现代 LLM Agent：历史能力如何拼到一起

```text
环境／用户输入 → 感知 → 结合记忆进行推理与规划
     ↑                         ↓
     └── 观察工具结果 ← 执行工具 ──┘
```

| 现代组件 | 对应的历史思路 | 作用 |
|---|---|---|
| 工具接口与执行规则 | 符号主义的显式动作和规则 | 明确“能做什么、怎样执行” |
| 规划与模块分工 | SHRDLU、心智社会 | 把目标拆成可执行步骤，协调多个能力 |
| LLM | 连接主义与预训练 | 理解开放指令，利用广泛的语言和知识能力 |
| 反馈循环 | 智能体与环境交互的思想 | 根据行动结果修正下一步决策 |
| 记忆 | 早期系统的状态维护和现代上下文管理 | 保留与当前任务相关的历史信息 |

这对应第 1 章的 **ReAct：Thought → Action → Observation**。Agent 根据目标选择行动，执行后观察结果，再决定下一步。

**两个“反馈”不要混淆：**根据工具结果修正下一步，是运行时调整当前任务的行动；强化学习根据奖励改进策略，通常涉及训练和参数更新。

## 七、读完本章应能回答

1. **为什么不能只靠 `IF-THEN` 写一个通用 Agent？** 开放世界里的知识、例外和状态变化无法经济地穷举。
2. **ELIZA 能对话，为什么不能说它理解了对话？** 它主要匹配输入并改写模板，缺乏语义模型和多轮状态。
3. **为什么 Agent 需要规划、记忆和工具？** 规划安排步骤，记忆保留状态，工具实际改变或查询环境；模型借反馈决定下一步。
4. **多模块协作解决了什么，又带来什么？** 它让复杂任务能分工完成，同时要求明确接口、协调机制和失败处理。

**一句话总结：** Agent 的发展是从“人把知识和动作规则写给机器”，逐步走向“机器从数据与交互中获得能力”，再把这些能力接入可观察、可执行、可反馈的任务闭环。
